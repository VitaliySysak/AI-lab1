Причина зупинок на ліміті: у кожному прогоні рівно один виклик інструмента (`list_files(.)`, у прогоні 8 — жодного), далі кроки без інструментів з ~2000 вихідних токенів кожен — упор у `max_tokens: 2048` адаптера. `qwen3:4b` — модель із роздумами: весь ліміт виходу йшов на міркування, JSON не встигав з'явитися, схема не проходила, цикл повертав помилку схеми, і так до `max-steps`. Контекст Ollama (4096) цього разу не причина: вхід на крок ~800 токенів.
Зупинки спрацювали як задумано: жодного зациклення за межі 12 кроків, жодного невалідного виходу як результату.
Валідний ≠ правильний: перша валідна пропозиція (прогін 7) переписує контракт `src/health.ts` (інтерфейс без zod і без `timestamp`) — модель не читала файлів і вигадала контракт; `health.test.ts` на ній упав би.

Що змінено: для прогонів на Ollama до системного промпту додано перемикач qwen3 `/no_think` (`scripts/measure-loop.ts`); задача, схема виходу, ліміти й інструменти ті самі. Для Gemini промпт не змінювався.
