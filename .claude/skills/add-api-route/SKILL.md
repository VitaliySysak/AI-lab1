# Додати API-маршрут

`<назва>` — назва маршруту: малі латинські літери, цифри, дефіси (приклад: `health`).
Еталон у репозиторії: `app/api/health/route.ts`, `src/health.ts`, `tests/health.test.ts`.

## Кроки

1. **Контракт.** Створи `src/<назва>.ts` зі схемою zod для тіла відповіді. Тип виводь зі схеми (`z.infer`), не пиши його вручну.
2. **Тест до коду.** Створи `tests/<назва>.test.ts`: імпортуй обробник відносним шляхом `../app/api/<назва>/route`, перевір статус, `content-type` і відповідність схемі (`safeParse`). Тест не ходить у мережу. Запусти `npm test` — новий тест має бути червоним.
3. **Обробник.** Створи `app/api/<назва>/route.ts`, експортуй функцію HTTP-методу (`GET`, `POST`…), відповідай через `Response.json(...)`.
   - Схему імпортуй відносним шляхом `../../../src/<назва>`, не через `@/`: `vitest.config.ts` не знає аліасу, і `npm test` впаде.
   - Якщо відповідь залежить від часу запиту або від даних, що змінюються, додай `export const dynamic = 'force-dynamic';`.
4. **Перевірка навички.** З кореня репозиторію: `node .claude/skills/add-api-route/scripts/check-route.mjs <назва>` (у копії для інших інструментів: `node .agents/skills/add-api-route/scripts/check-route.mjs <назва>`). Код 1 — виправ рядки `FAIL` і запусти знову.
5. **Готово** — лише коли `check-route.mjs` повернув 0 і зелені перевірки з AGENTS.md. У виводі `npm run build` покажи рядок маршруту: `ƒ /api/<назва>` (динамічний) чи `○` (статичний) — і поясни, чому саме так.

## Межі

- Не змінюй наявні тести й схеми, щоб новий код пройшов.
- `package.json` не чіпай: нову залежність додає людина.
- `npm run dev` не запускай: він дописує блок Next.js в AGENTS.md.
